## 四、前端对接设计

### 4.1 分层

```
src/
├─ api/
│  ├─ request.js    axios 实例 + 请求/响应拦截器 + ApiError + 401 处理
│  └─ index.js      资源 CRUD 工厂 + 认证 + 领域业务接口
├─ stores/
│  ├─ auth.js       token / user / 登录 / 登出 / 令牌校验
│  └─ data.js       水合缓存 + 服务端查询 + 写透（乐观更新 & 回滚）
├─ router/index.js  hash 路由 + 全局守卫（登录态校验）
├─ layouts/         应用外壳（侧栏 / 顶栏 / 内容区）
└─ views/           11 个业务页面
```

### 4.2 请求层（`api/request.js`）

- **请求拦截**：自动注入 `Authorization: Bearer <token>`
- **响应拦截**：统一拆包 `{code,message,data}` → 直接返回 `data`；`code !== 0` 转成 `ApiError` 抛出
- **错误归一**：`ApiError { message, code, status, errors }`，并提供 `fieldError(field)` 供表单回填
- **超时**：15s；超时与断网给出区分文案
- **401**：由 `main.js` 注册的处理函数捕获 → 清理令牌 → 跳登录页并携带 `redirect`

### 4.3 数据层（`stores/data.js`）

| 能力 | 方法 | 说明 |
| --- | --- | --- |
| 首屏水合 | `hydrate()` | 调用 `GET /bootstrap` 一次性拉全量数据进缓存 |
| 服务端查询 | `query(resource, params)` | 真实分页/筛选/排序，结果合并进缓存 |
| 新建 | `save(resource, payload)` | POST → 写入缓存 |
| 更新 | `edit(resource, id, patch)` | PATCH → 覆盖缓存 |
| 删除 | `destroy(resource, id)` | DELETE → 移出缓存 |
| 看板拖拽 | `changeWorkItemStatus(id, status)` | **乐观更新 + 失败回滚** |
| 计划执行 | `executeTestPlan(planId, caseId, result)` | 同步计划、用例、自动创建的缺陷 |
| 评论 / 自动化 | `postComment` / `toggleAutomation` / `runAutomation` | 写透 |
| 重置 | `resetDemo()` | `POST /system/reset` 后重新水合 |

设计取舍：**读走缓存**（视图同步取用，避免层层 `await`），**写一律走接口再更新缓存**（保证服务端是唯一事实源）。列表类数据用 `query()` 走服务端分页，不使用本地过滤冒充。

## 五、加载 / 成功 / 失败状态处理

| 场景 | 表现 |
| --- | --- |
| 首屏水合中 | 全屏 `boot-screen`（品牌动画 + "正在从服务端同步数据"） |
| 首屏水合失败 | 全屏错误态：原因 + "请确认后端服务已在 127.0.0.1:8080 启动" + **重新加载 / 退出登录** 按钮 |
| 写操作进行中 | 顶栏出现薄荷绿流动进度条（`data.pending > 0`）；提交按钮变 `保存中…` 并禁用 |
| 列表加载中 | Element Plus `v-loading` 遮罩 + 骨架占位 |
| 成功 | `ElMessage.success` 明确反馈（如"需求已创建"） |
| 失败 | `ElMessage.error` 展示后端 `message`；**400 时把 `errors[]` 回填到对应表单项红字** |
| 令牌过期 | 自动清理令牌 → 提示"登录已过期" → 跳登录页 |

**错误处理分层**

| 层 | 处理方式 |
| --- | --- |
| 网络层（超时/断网，`code=-1`） | "请求超时，请稍后重试" / "网络异常，请确认后端服务（:8080）已启动" |
| 401 | 清理令牌 → 跳登录页（带 `redirect`） |
| 400 | 解析 `errors[]` → 表单字段级提示 |
| 404 | 提示"数据已被删除"，刷新列表 |
| 409 / 422 | 直接展示 `message`（业务语义已可读） |
| 5xx | "服务异常，请稍后重试" + 控制台打印 `code` |

## 六、数据校验：前后端一致

后端以 **Schema 白名单**（`support/Schemas.java`）为唯一权威，前端表单校验与之对齐：

| 字段 | 后端规则 | 前端表现 |
| --- | --- | --- |
| `title` | 必填，2~120 字 | `el-form-item required` + `:error` 绑定后端错误 |
| `identifier` | 必填，2~6 位、字母开头、唯一 | 输入框 + 后端 409/400 提示 |
| `points` | 整数 0~100 | `el-input-number :min="0" :max="100"` |
| `priority` / `status` / `type` | 枚举 | `el-select` 仅提供合法选项 |
| `productId` / `projectId` | 引用必须存在 | `el-select` 选项来自缓存 |
| `code` / `runs` / `lastRun` | 只读，服务端生成 | 前端不提交该字段 |

要点：
1. 前端 `el-select` 天然约束枚举，但**仍可能被绕过**，后端必须独立校验（已实现）。
2. 后端校验失败返回 `{code:40001, errors:[{field,message}]}`，前端统一回填，**不在前端重复实现一遍规则文案**。
3. `readonly` 字段即使被客户端伪造传入也会被后端丢弃（防越权写入）。

## 七、联调关键点（重点）

1. **同源代理优先于 CORS**
   开发期用 `dev-server.py` / Vite `server.proxy` 把 `/api` 代理到 `:8080`，彻底规避跨域与 OPTIONS 预检。后端虽已开启 CORS 白名单，但生产环境建议由 Nginx 同源反代。

2. **字段命名以接口文档为准**
   `description`（非 `desc`）、`triggerEvent`（非 `trigger`）、`conditionExpr`（非 `condition`）、`occurredAt`（非 `time`）—— 这三个是因为 SQL 保留字改的名，最容易踩。

3. **空值不输出**
   后端配置 `default-property-inclusion: non_null`，响应里**没有的字段就是空**。前端取值必须兜底（`row.description ?? ''`），否则 `undefined` 会渲染成 "undefined"。

4. **日期格式**
   提交日期用 `YYYY-MM-DD`（`el-date-picker` 的 `value-format="YYYY-MM-DD"`），后端按 `LocalDate` 解析；返回的 `createdAt` 形如 `2026-10-01T16:48:29`，可直接 `new Date()`。

5. **数值字段显式转换**
   表单里 `points` 可能拿到字符串，提交前 `Number()` 转换，否则后端返回 400。

6. **分页上限**
   后端 `pageSize` 上限 500 且会自动收敛；前端勿传超大值，看板类场景用 `pageSize: 200` 一次取全。

7. **401 处理的死循环防护**
   登录页是 `meta.public`，401 处理器在 `auth.token` 为空时直接返回，避免登录失败本身又触发跳转。跳转失败时有 `window.location.hash` 兜底。

8. **写操作的幂等与回滚**
   看板拖拽采用"乐观更新 + 失败回滚"：先动 UI 再发请求，失败时把卡片放回原列并提示，避免"卡住不动"的错觉。

9. **业务副作用的可见性**
   用例执行失败会**按自动化规则自动创建缺陷**，接口在 `autoCreatedDefect` 字段返回；前端必须显式提示，否则用户不知道数据被改了。

10. **后端未启动时的表现**
    代理层返回 `502` + 统一 JSON，前端走"网络层错误"分支提示，而不是白屏。

## 八、当前环境的已知限制

**沙箱内无法创建 Node 子进程**（`spawnSync ... EBUSY` 对 `cmd.exe` / `java.exe` / `node.exe` 均复现），由此产生两个连带影响：

1. `npm install` 的 postinstall 脚本（如 esbuild）无法执行；
2. **Vite 依赖 esbuild 子进程，无法在本环境启动 dev server / 构建**。

因此本项目采用**双模式**设计，源码完全通用：

- **当前环境**：`index.html` 通过 `importmap` 指向 `vendor/` 下的 ESM 产物，浏览器原生加载，配合 `scripts/dev-server.py` 提供静态托管 + API 代理。
- **标准环境**：`package.json` / `vite.config.js` 齐备，`npm i && npm run dev` 即可切换到 Vite 工作流；源码同样支持（裸模块说明符在 Vite 下由 `node_modules` 解析，`importmap` 不生效也不冲突）。

> 注意：由于使用运行时模板编译，Vite 模式下需把 `vue` 别名为 `vue/dist/vue.esm-bundler.js`（完整版，含编译器）；`vite.config.js` 中已配置。
