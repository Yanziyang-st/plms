# PLMS 后端接口文档

| 项 | 值 |
| --- | --- |
| 服务名 | `plms-service` |
| 技术栈 | Spring Boot 3.3.7 + MyBatis-Plus 3.5.9 + MySQL 8 + Nacos(可选) |
| Base URL | `http://127.0.0.1:8080/api` |
| 数据格式 | `application/json; charset=UTF-8` |
| 认证方式 | JWT（`Authorization: Bearer <token>`） |
| 令牌有效期 | 12 小时（`plms.jwt.expire-hours`） |

---

## 一、通用约定

### 1.1 统一响应信封

**成功**

```json
{ "code": 0, "message": "success", "data": { } }
```

**失败**（HTTP 状态码同时具备语义）

```json
{
  "code": 40001,
  "message": "参数校验失败：标题不能为空",
  "data": null,
  "errors": [ { "field": "title", "message": "标题不能为空" } ]
}
```

> `errors` 仅在 **400 参数校验失败**时出现，供前端做字段级红字提示；其余错误只有 `code` / `message` / `data`。

### 1.2 状态码与业务错误码

| 业务 code | HTTP | 含义 | 触发场景 |
| --- | --- | --- | --- |
| `0` | 200 / 201 | 成功 | —— |
| `40001` | 400 | 参数校验失败 | 必填缺失、长度/数值越界、枚举非法、日期格式错误、引用不存在 |
| `40101` | 401 | 未认证或令牌失效 | 缺少/非法/过期 `Authorization` |
| `40102` | 401 | 账号或密码错误 | 登录失败 |
| `40301` | 403 | 无操作权限 | 预留（当前按登录态放行） |
| `40401` | 404 | 资源不存在 | 详情/更新/删除的目标 ID 不存在 |
| `40501` | 405 | 请求方法不支持 | 对只读路径使用了错误方法 |
| `40901` | 409 | 数据冲突 | 唯一约束冲突（如产品标识符重复）、存在下级引用时删除 |
| `42201` | 422 | 业务规则不通过 | 语义合法但不满足业务约束（如用例不属于该测试计划） |
| `50001` | 500 | 服务端异常 | 未捕获异常 |

### 1.3 列表查询约定（所有集合资源通用）

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `page` | int | `1` | 页码，从 1 开始 |
| `pageSize` | int | `20` | 每页条数，**上限 500**，超出自动收敛 |
| `keyword` | string | — | 关键字模糊匹配（各资源的检索字段见 §3.1） |
| `ids` | string | — | 逗号分隔的 ID 列表，等价 `IN` 查询 |
| `sort` | string | `createdAt` | 排序字段（仅接受该资源白名单内字段，否则回落默认） |
| `order` | string | `desc` | `asc` / `desc` |
| 其他字段 | string | — | **白名单内的字段**直接作为等值筛选条件，例如 `?status=已完成&productId=p1` |

**分页返回结构**

```json
{ "code": 0, "message": "success",
  "data": { "list": [ ], "total": 12, "page": 1, "pageSize": 20 } }
```

> 非白名单的查询参数会被**静默忽略**（不报错），避免注入与 500。

### 1.4 权限模型（RBAC）

除认证外，后端按 **模块 + 动作** 做访问控制：`GET/HEAD` 需 `模块:read`，其余方法需 `模块:write`，越权返回 `403 / 40301`。

| 模块 | 覆盖路径 |
| --- | --- |
| `product` | `/api/products`、`/api/requirements` |
| `project` | `/api/projects`、`/api/sprints`、`/api/work-items` |
| `test` | `/api/test-libraries`、`/api/test-cases`、`/api/test-plans` |
| `knowledge` | `/api/wiki-spaces`、`/api/wiki-pages` |
| `collab` | `/api/topics` |
| `automation` | `/api/automations` |
| `ai` | `/api/agents` |
| `metrics` | `/api/metrics` |
| `admin` | `/api/users`、`/api/system/reset` |

仅需登录、不做模块限制的路径：`/api/bootstrap`（内部按权限过滤）、`/api/search`、`/api/comments`、`/api/links`、`/api/activities`、`/api/export`。

角色 → 权限映射见 `GET /api/auth/permissions`；`管理员` 拥有全部权限。

### 1.5 写操作约定

- `POST` 新建 → **201**，返回完整实体
- `PATCH / PUT` 更新 → **200**，返回更新后实体。`PATCH` 为**部分更新**：只传要改的字段，未传字段保持原值；**空对象 `{}` 返回 400**
- `DELETE` 删除 → **200**（当前项目统一返回 JSON 信封，非 204）
- **只读字段**（如业务编号 `code`）由服务端生成，客户端传入会被忽略
- **未知字段**一律丢弃（白名单机制，防止越权写入）

## 二、认证接口

### 2.1 登录

`POST /api/auth/login`　**无需令牌**

| 入参 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `username` | string | 是 | 登录账号 |
| `password` | string | 是 | 密码 |

```json
// 请求
{ "username": "demo_admin", "password": "123456" }
```

```json
// 200 响应
{ "code": 0, "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "tokenType": "Bearer",
    "expiresIn": 43200,
    "user": { "id": "u1", "name": "张伟", "username": "demo_admin", "role": "管理员", "dept": "研发一部", "color": "#13a884" }
  } }
```

- `401 / 40102` 账号或密码错误
- `400 / 40001` 账号或密码为空
- **响应体永不包含 `password` 字段**

### 2.2 当前用户

`GET /api/auth/me` → `200`，`data` 为当前登录用户对象。

### 2.3 登出

`POST /api/auth/logout` → `200`。JWT 无状态，服务端不维护会话，**客户端需自行清除本地令牌**。

### 2.4 健康检查

`GET /api/system/health`　**无需令牌** → `{ "code":0, "data": { "service":"plms-service", "status":"UP", "time":"..." } }`

## 三、资源接口

### 3.1 资源清单

全部资源均提供 **5 个标准接口**：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/{resource}` | 列表（分页/筛选/排序/关键字） |
| `GET` | `/api/{resource}/{id}` | 详情 |
| `POST` | `/api/{resource}` | 新建（201） |
| `PATCH` `PUT` | `/api/{resource}/{id}` | 更新（部分更新） |
| `DELETE` | `/api/{resource}/{id}` | 删除 |

| 资源 | 路径 | 中文名 | 关键字检索字段 | 可筛选字段 |
| --- | --- | --- | --- | --- |
| 产品 | `/api/products` | 产品 | `name` | name/identifier/owner/status |
| 需求 | `/api/requirements` | 需求/工单 | `title` | productId/type/priority/status/assignee/source/points |
| 项目 | `/api/projects` | 项目 | `name` | identifier/type/status/owner/productId |
| 迭代 | `/api/sprints` | 迭代 | `name` | projectId/status |
| 工作项 | `/api/work-items` | 工作项 | `title` | projectId/sprintId/type/priority/status/assignee |
| 测试库 | `/api/test-libraries` | 测试库 | `name` | owner/productId |
| 测试用例 | `/api/test-cases` | 测试用例 | `title` | libraryId/module/type/priority/maintainer/lastResult |
| 测试计划 | `/api/test-plans` | 测试计划 | `name` | projectId/libraryId/status/owner |
| 知识空间 | `/api/wiki-spaces` | 知识空间 | `name` | owner |
| 知识页面 | `/api/wiki-pages` | 知识页面 | `title` | spaceId/parentId/author |
| 协作话题 | `/api/topics` | 协作话题 | `title` | author |
| 自动化规则 | `/api/automations` | 自动化规则 | `name` | enabled/triggerEvent |
| 智能体 | `/api/agents` | 智能体 | `name` | role |
| 用户 | `/api/users` | 用户 | `name` | role/dept |
| 活动日志 | `/api/activities` | 活动日志 | `target` | userId/action |

> 另有一个**内部资源** `/api/topic-comments`（话题评论），支持标准 CRUD；前端通常无需直接调用。

**示例**

```
GET /api/requirements?status=已完成&priority=高&page=1&pageSize=20&sort=points&order=desc
GET /api/work-items?projectId=proj1&ids=w1,w2,w3
```

### 3.2 首屏水合接口

`GET /api/bootstrap` → `200`

一次性返回前端首屏所需的全部集合，**用于避免 N 次并发请求**。

```json
{ "code": 0, "data": {
    "users": [...], "products": [...], "requirements": [...], "projects": [...],
    "sprints": [...], "workItems": [...], "testLibraries": [...], "testCases": [...],
    "testPlans": [...], "wikiSpaces": [...], "wikiPages": [...],
    "topics": [ { "id":"t1", "...": "...", "comments": [ { "id":"c1", "author":"u3", "content":"..." } ] } ],
    "automations": [...], "agents": [...], "activities": [...],
    "meta": { "serverTime": "2026-10-01T16:48:29", "schemaVersion": 1 }
} }
```

> `topics` 已内嵌 `comments` 数组，前端无需再单独请求评论。

## 四、领域业务接口

### 4.1 看板：工作项状态流转

`PATCH /api/work-items/{id}/status`

| 入参 | 类型 | 必填 | 取值 |
| --- | --- | --- | --- |
| `status` | string | 是 | `待处理` / `进行中` / `待测试` / `已完成` |

**业务规则**：状态变更后**自动重算所属项目进度**（已完成工作项 ÷ 工作项总数 × 100）。

```json
// 200
{ "code": 0, "message": "状态已更新", "data": {
    "item": { "id":"w1", "code":"OAV2-100", "status":"已完成", "...": "..." },
    "project": { "id":"proj1", "progress": 63, "...": "..." }
} }
```

- `400 / 40001` 状态取值非法
- `404 / 40401` 工作项不存在

### 4.2 测试：记录用例结果

`POST /api/test-cases/{id}/result`　入参 `{ "result": "通过" }`
取值：`通过` / `失败` / `阻塞` / `未执行` → `200`，返回更新后的用例。

### 4.3 测试：执行测试计划

`POST /api/test-plans/{id}/execute`

| 入参 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `caseId` | string | 是 | 计划内的用例 ID |
| `result` | string | 是 | `通过` / `失败` / `阻塞` / `未执行` |

**业务规则**
1. 用例必须属于该计划，否则 `422 / 42201`
2. 结果写入 `plan.results[caseId]`，同时同步 `testCase.lastResult`
3. 计划内所有用例均已执行时，计划状态自动置为 `已完成`
4. **结果为「失败」且自动化规则 `a3` 处于启用状态时**，自动创建「缺陷」工作项并指派给用例维护人，同时规则 `runs + 1`

```json
// 200
{ "code": 0, "message": "执行结果已提交", "data": {
    "plan": { "id":"tp1", "results": { "tc2": "失败" }, "status": "进行中" },
    "case": { "id":"tc2", "lastResult": "失败" },
    "autoCreatedDefect": { "id":"wi_xxx", "code":"OAV2-116", "title":"【缺陷】审批抄送通知下发 执行失败", "priority":"高" }
} }
```

### 4.4 协作：发表评论

`POST /api/topics/{id}/comments`　入参 `{ "content": "..." }`（1~1000 字）→ **201**，返回评论对象。

### 4.5 自动化：启停 / 立即执行

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/automations/{id}/toggle` | 切换 `enabled`，返回规则 |
| `POST` | `/api/automations/{id}/run` | `runs + 1` 并刷新 `lastRun`，返回规则 |

### 4.6 效能度量

`GET /api/metrics/overview` → `200`

```json
{ "code": 0, "data": {
  "workItems": { "total": 16, "byStatus": {"已完成":7,"进行中":3}, "byType": {"任务":9}, "totalPoints": 76, "donePoints": 30 },
  "requirements": { "total": 12, "byStatus": { "...": 0 } },
  "projects": { "total": 3, "active": 2, "avgProgress": 63 },
  "tests": { "cases": 12, "byResult": {"通过":8}, "passRate": 67 },
  "delivery": { "velocity": [32,41,38,52,47,61], "velocityLabels": ["S1"...], "burndown": [120,...,30] }
} }
```

`GET /api/metrics/members` → 成员效能列表，按已完成故事点降序：

```json
{ "code": 0, "data": [ { "user": {...}, "total": 5, "done": 2, "points": 8 } ] }
```

### 4.7 全局搜索

`GET /api/search?q=审批` → `200`，跨需求/工作项/用例/文档/项目/产品/话题检索，最多返回 30 条。

```json
{ "code": 0, "data": [ { "type":"需求", "resource":"requirements", "id":"r1", "title":"支持多级流程审批与抄送", "sub":"OA-REQ-001 · 待评审" } ] }
```

`q` 为空 → `400 / 40001`。

### 4.8 系统：重置演示数据

`POST /api/system/reset` → `200`，清空全部业务表并重新灌入种子数据，返回各表计数。**需要 `admin:write` 权限。**

### 4.9 工作项状态机

`GET /api/work-items/{id}/transitions` → 当前状态与可流转状态：

```json
{ "code": 0, "data": { "id":"w1", "current":"进行中", "allowed":["待测试","已完成","待处理"], "closed": false } }
```

状态流转受状态机约束，非法流转返回 `422 / 42201`：

| 当前状态 | 可流转到 |
| --- | --- |
| 待处理 | 进行中、已完成 |
| 进行中 | 待测试、已完成、待处理 |
| 待测试 | 已完成、进行中、待处理 |
| 已完成 | 进行中（重新打开） |

`PATCH /api/work-items/{id}/status` 在流转合法时**联动重算项目进度**；重复设置为同一状态也返回 `422`。

### 4.10 通用评论

评论可挂在任意实体上（`targetType` ∈ `work-item` / `requirement` / `test-case` / `topic`）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/comments?targetType=&targetId=` | 查询某对象的评论 |
| `POST` | `/api/comments` | 发表评论（201）。`{ targetType, targetId, content }`，1~1000 字 |
| `DELETE` | `/api/comments/{id}` | 删除评论。**仅作者本人或管理员**，否则 403 |
| `GET` `POST` | `/api/work-items/{id}/comments` | 工作项评论的便捷端点 |
| `GET` `POST` | `/api/topics/{id}/comments` | 话题讨论的便捷端点 |

### 4.11 实体关联与需求追踪

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/links?entityType=&entityId=` | 查询某实体的全部关联（双向） |
| `POST` | `/api/links` | 建立关联（201）。`{ sourceType, sourceId, targetType, targetId, linkType }` |
| `DELETE` | `/api/links/{id}` | 解除关联 |
| `GET` | `/api/trace/requirement/{id}` | 单个需求的追溯详情 |
| `GET` | `/api/trace/matrix?productId=` | 需求追踪矩阵（RTM） |

`entityType` / `sourceType` / `targetType` 取值：`requirement`、`work-item`、`test-case`；`linkType`：`implements`（实现）、`verifies`（验证）、`relates`（相关）。

- 关联到自身 → `400`；源/目标不存在 → `404`；重复关联 → `409`
- `trace/requirement/{id}` 返回 `{ requirement, workItems[], testCases[], coverage }`，其中 `testCases` **包含经工作项间接关联的用例**
- `trace/matrix` 返回 `{ rows: [{ requirement, workItems, testCases, coverage }], summary: { total, fullyCovered, coverageRate } }`

### 4.12 测试计划：用例增删

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/test-plans/{id}/cases` | 追加用例。`{ caseIds: [] }`，已存在的会被忽略；全部重复返回 422 |
| `DELETE` | `/api/test-plans/{id}/cases/{caseId}` | 移除用例；移除后计划为空返回 422 |

### 4.13 批量操作（所有资源通用）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/{resource}/batch-delete` | `{ ids: [] }`，单次最多 100 条 |
| `POST` | `/api/{resource}/batch-update` | `{ ids: [], patch: {} }`，patch 同样走白名单校验 |

两者都**逐条校验**并返回明细：

```json
{ "code": 0, "message": "批量删除完成",
  "data": { "requested": 3, "success": 2, "failed": 1,
            "failures": [ { "id": "p1", "message": "该产品下仍有需求/工单，无法删除" } ] } }
```

全部失败时返回 `422`。

### 4.14 数据导出

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/export/resources` | 支持导出的资源清单 |
| `GET` | `/api/export/{resource}` | 导出 CSV，支持与列表接口相同的筛选参数 |
| `GET` | `/api/export/metrics/members` | 成员效能报表 |

- 可导出资源：`requirements`、`work-items`、`test-cases`、`users`、`projects`、`activities`
- 响应为 `text/csv; charset=UTF-8`，**带 UTF-8 BOM**（Excel 直接打开不乱码），并设置 `Content-Disposition`
- 单次最多导出 500 行；不支持的资源返回 `400`

### 4.15 用户管理

除标准 CRUD 外的专用端点：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/users` | 新建成员。`{ name, username, password?, role, dept, email }` |
| `POST` | `/api/users/{id}/reset-password` | 重置密码（不传则重置为 `123456`） |
| `POST` | `/api/users/{id}/toggle` | 启用 / 停用 |
| `GET` | `/api/auth/permissions` | 当前用户权限点 + 全量角色矩阵 |

**约束（均返回 4xx）**：账号唯一（409）、账号格式 `^[A-Za-z][A-Za-z0-9_]{2,29}$`（400）、密码 6~32 位（400）、邮箱格式（400）；不能删除/停用自己、不能移除最后一名管理员（422）；停用后登录返回 403。

> 响应体中**永不包含 `password` 字段**；新建成员若不传密码，默认 `123456`。

### 4.16 工作项子项（父子结构）

工作项支持**最多两层**的父子结构：顶层工作项可挂若干「子任务」，子任务不能再挂子项。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/work-items/tree?projectId=` | 项目工作项树：顶层 + 子项 + 每项汇总 + 统计 |
| `GET` | `/api/work-items/{id}/children` | 子项列表 + 汇总 |
| `GET` | `/api/work-items/{id}/tree` | 自身 + 子项 + 父项 + 兄弟项 |
| `GET` | `/api/work-items/{id}/subtask-summary` | 仅子项汇总 |

`GET /api/work-items/{id}/children` 返回：

```json
{ "code": 0, "data": {
  "parentId": "w1",
  "children": [ { "id":"ws1", "code":"OAV2-100-S1", "type":"子任务", "status":"已完成", "...": "" } ],
  "summary": { "parentId":"w1", "total":2, "done":1, "pending":1,
               "progress":50, "points":5, "allDone":false } } }
```

`GET /api/work-items/tree?projectId=proj1` 返回 `{ nodes: [{ item, children, summary }], stat: { topLevel, subtasks, orphan } }`。

创建 / 更新子项只需在 `work-items` 的请求体中带上 `parentId`。

**约束（全部返回 400）**

| 情况 | 提示 |
| --- | --- |
| `parentId` 指向自身 | 父工作项不能是自身 |
| `parentId` 不存在 | 父工作项不存在：xxx |
| 父项跨项目 | 父工作项必须与当前工作项属于同一项目 |
| 父项本身是「子任务」 | 「子任务」不能再挂子项（工作项层级最多两层） |
| 形成环路 | 父工作项设置形成了循环引用 |

**类型归一化**：服务端保证 `有父项 ⇔ type = "子任务"`。
传了 `parentId` 会自动把 `type` 设为「子任务」；把 `parentId` 置空会自动把遗留的「子任务」类型改回「任务」。

**其他规则**

- 父项仍有未完成子项时，`PATCH /api/work-items/{id}/status` 流转到「已完成」返回 **422**
- 父项仍有子项时，`DELETE /api/work-items/{id}` 返回 **409**
- **统计口径**：项目进度（`project.progress`）与故事点（`metrics.workItems.totalPoints` / `donePoints`）
  **只统计顶层工作项**，避免父子重复计入；`metrics.workItems` 额外返回 `topLevel`、`subtasks` 两个计数

**置空可空字段**：PATCH 时显式传 `null` 或 `""` 表示**清空该字段**（如 `{"parentId": null}` 移出子任务、
`{"sprintId": null}` 取消迭代归属）。必填字段显式传空则返回 400。

## 七、前后端联调关键点

### 7.1 认证链路
1. 登录成功后把 `token` 存到 `localStorage`，后续所有请求由 axios 请求拦截器统一注入 `Authorization: Bearer <token>`。
2. 响应拦截器捕获 **401**：清除本地令牌并跳转登录页，**避免在登录页本身触发死循环**。
3. 令牌 12 小时过期，过期后端返回 `401 / 40101`，前端应提示"登录已过期，请重新登录"。

### 7.2 长整型与精度
本项目 ID 全部为**字符串**，不存在 JS 大数精度问题；若后续改用雪花算法 Long 主键，需在 Jackson 中配置 `Long → String` 序列化。

### 7.3 数值与空值
- `points` / `progress` 等为整数，前端表单需做 `Number()` 转换后再提交，否则后端返回 `400`。
- 后端 `data` 中**空值字段不输出**（`default-property-inclusion: non_null`），前端取字段时需做空值兜底（`?? ''`）。

### 7.4 日期
- 提交日期用 `YYYY-MM-DD`（如 `2026-10-05`），后端按 `LocalDate` 解析；提交日期时间用 ISO-8601。
- 后端返回的 `createdAt` 为 `2026-10-01T16:48:29`，前端可直接 `new Date(...)` 解析。

### 7.5 分页与筛选
- 前端列表页统一维护 `page` / `pageSize` / `keyword` / 各筛选字段的 state，变更后重新拉取。
- **筛选字段名必须与后端字段同名**（`productId`、`status`…），非白名单字段会被静默忽略，表现为"筛选没生效"，排查时优先看参数名拼写。

### 7.6 错误处理分层
| 层 | 处理 |
| --- | --- |
| 网络层（超时/断网） | 统一提示"网络异常，请检查服务是否启动" + 重试按钮 |
| HTTP 401 | 清除令牌 → 跳登录页 |
| HTTP 400 | 读取 `errors[]`，把 `message` 绑定到对应 `field` 做表单红字提示 |
| HTTP 404 | 提示"数据已被删除"，并刷新列表 |
| HTTP 409 / 422 | 直接展示 `message`（业务语义已可读） |
| HTTP 5xx | 提示"服务异常，请稍后重试"，并打印 `code` 便于排查 |

### 7.7 开发期跨域
后端已开启 CORS（允许 `http://localhost:*` / `http://127.0.0.1:*`）。**推荐做法**是在 Vite 中配置代理，让前端以同源方式访问，彻底规避跨域与预检（OPTIONS）问题：

```js
// vite.config.js
server: { proxy: { '/api': { target: 'http://127.0.0.1:8080', changeOrigin: true } } }
```

### 7.8 端口占用提醒
本机存在环境变量 `SERVER__PORT=3703`（宿主服务占用），会覆盖 `application.yml` 的 `server.port`。启动后端时需显式指定端口：

```bash
unset SERVER__PORT && mvn spring-boot:run -Dspring-boot.run.arguments=--server.port=8080
```
