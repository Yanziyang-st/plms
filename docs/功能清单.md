## 一、补齐前的缺口审计

| # | 缺口 | 性质 | 影响 |
| --- | --- | --- | --- |
| 1 | 需求跟踪矩阵按**数组下标**配对需求/工作项/用例 | **假实现** | 页面像是有追溯能力，实际数据无关联关系，是"看起来对"的典型 |
| 2 | `ErrorCode.FORBIDDEN` 从未被使用，权限表只是静态展示 | **未实现** | 任何登录用户可操作任意模块；后台的角色权限矩阵形同虚设 |
| 3 | 工作项无详情页，无法查看描述/评论/关联 | **缺失** | PLM 最核心的协作载体不可用 |
| 4 | 评论只支持话题 | **不完整** | 需求、工作项、用例无法讨论 |
| 5 | 状态可从任意态跳到任意态 | **逻辑不完整** | "待处理"能直接变"已完成"，过程不可信 |
| 6 | 跨字段规则缺失（日期先后、父子环、同空间、邮箱格式） | **边界未覆盖** | 可造出"结束早于开始"、页面父子成环等脏数据 |
| 7 | 删除约束只覆盖 4 类资源，且不清理关联数据 | **边界未覆盖** | 产生孤儿关联与孤儿评论 |
| 8 | 无批量操作 | **缺失** | 只能逐条操作 |
| 9 | 无导出能力（前端临时拼 CSV） | **不完整** | 导出口径与筛选条件不一致 |
| 10 | 用户管理只能改角色，不能新增/改密/启停 | **缺失** | 无法真正管理成员 |
| 11 | 测试计划用例创建后不可增删 | **逻辑不完整** | 计划一旦建错只能重建 |
| 12 | 搜索无类型过滤与条数上限 | **不完整** | 结果不可控 |
| 13 | 知识页面不能删除、不能建子页面 | **缺失** | 树形结构无法维护 |
| 14 | 迭代只读，不能新建/编辑/删除 | **缺失** | Scrum 节奏无法维护 |
| 15 | 无结构迁移机制 | **可维护性** | 加字段就要手工改库 |

## 二、补齐后的功能清单

### 2.1 权限与安全（RBAC）

| 能力 | 实现 |
| --- | --- |
| 角色 → 权限点映射 | 9 个模块 × 读写动作，7 种角色各有独立权限集 |
| 服务端强制校验 | `PermissionInterceptor` 按「模块 + 读写」拦截，**GET 需 read、写操作需 write**，越权返回 `403 / 40301` |
| 水合数据过滤 | `GET /api/bootstrap` 按读权限过滤集合，**越权数据不下发** |
| 前端导航过滤 | 侧栏按 `canRead(module)` 隐藏无权模块 |
| 按钮级显隐 | 新建/编辑/删除/批量等按钮按 `canWrite(module)` 渲染 |
| 权限矩阵 | `GET /api/auth/permissions` 下发权限点 + 角色矩阵，后台管理页动态渲染 |
| 账号启停 | `enabled` 字段，停用后**登录直接 403**，且不能停用自己/最后一名管理员 |
| 密码安全 | BCrypt 存储；响应体永不包含 `password`；重置密码接口独立 |
| 越权写保护 | readonly 字段（业务编号等）客户端传入一律丢弃 |

### 2.2 需求追踪（PLM 核心）

| 能力 | 实现 |
| --- | --- |
| 关联表 | `plm_link(source_type, source_id, target_type, target_id, link_type)` + 唯一约束 |
| 关联类型 | `implements`（实现）/ `verifies`（验证）/ `relates`（相关） |
| 建立/解除关联 | 校验源目标存在性、禁止自关联、重复关联返回 409 |
| 需求追溯详情 | `GET /api/trace/requirement/{id}` → 关联工作项、关联用例、覆盖度（**用例含经工作项间接关联的部分**） |
| 追踪矩阵 RTM | `GET /api/trace/matrix` → 每行需求 + 实现工作项 + 验证用例 + 覆盖状态，含 `coverageRate` 汇总 |
| 前端呈现 | 矩阵页展示真实编号与状态；需求列表带「已覆盖/部分/未关联」标记；需求详情抽屉展示覆盖度与未闭环提示 |
| 关联维护 UI | 工作项详情抽屉内可建立/解除关联，候选项按需求/用例/工作项分组 |

### 2.3 协作与评论

| 能力 | 实现 |
| --- | --- |
| 通用评论 | `plm_comment(target_type, target_id, ...)` 统一承载工作项/需求/用例/话题 |
| 发表评论 | 校验对象类型合法、对象存在、内容 1~1000 字 |
| 删除评论 | **仅作者本人或管理员**，否则 403 |
| 工作项评论 | 详情抽屉内直接发表/删除，看板卡片显示评论数 |
| 话题讨论 | 迁移到统一评论体系，`/api/topics/{id}/comments` 端点保持不变 |

### 2.4 状态机与流程约束

| 能力 | 实现 |
| --- | --- |
| 状态机定义 | 待处理→{进行中,已完成}；进行中→{待测试,已完成,待处理}；待测试→{已完成,进行中,待处理}；已完成→{进行中} |
| 查询可流转 | `GET /api/work-items/{id}/transitions` |
| 非法流转 | 返回 `422` 并给出「可流转状态」提示；重复设置同一状态同样拒绝 |
| 看板拖拽 | 前端镜像同一状态机，**不可投放的列半透明化**，非法拖拽给出明确提示 |
| 进度联动 | 流转成功后自动重算所属项目进度（已完成/总数） |

### 2.5 校验补全（边界情况）

| 类别 | 规则 |
| --- | --- |
| 字段级 | 必填、长度、数值区间、枚举白名单、格式正则（标识符/邮箱/账号）、引用存在性 |
| 跨字段 | 项目/迭代/工作项/测试计划的**开始日期不得晚于结束日期** |
| 树形约束 | 父页面不能是自身、必须同空间、**沿父链检测环路**、父页面必须存在 |
| 集合约束 | 测试计划的 `caseIds` 至少 1 条且每条都必须存在 |
| 唯一约束 | 产品/项目标识符、需求/工作项/用例业务编号、用户登录账号 |
| 长度上限 | 分页 `pageSize` 上限 500；批量操作单次上限 100；评论 ≤1000 字 |
| 白名单 | 非 schema 字段一律丢弃；不可筛选的查询参数静默忽略（不报 500） |

### 2.6 删除约束与级联

| 资源 | 约束 | 级联清理 |
| --- | --- | --- |
| 产品 | 有需求/工单时 409 | — |
| 项目 | 有工作项或迭代时 409 | — |
| 迭代 | 有工作项时 409 | — |
| 测试库 | 有用例时 409 | — |
| 测试用例 | 被测试计划引用时 409（提示引用数） | 关联关系、评论 |
| 知识空间 | 有页面时 409 | — |
| 知识页面 | 有子页面时 409 | — |
| 用户 | 不能删自己、不能删最后一名管理员、名下仍有工作项时 409 | — |
| 需求 / 工作项 | — | 关联关系（双向）、评论 |
| 话题 | — | 该话题全部评论 |

### 2.7 批量操作

| 能力 | 实现 |
| --- | --- |
| 批量删除 | `POST /api/{resource}/batch-delete`，逐条校验，返回成功/失败明细 |
| 批量更新 | `POST /api/{resource}/batch-update`，patch 走白名单校验 |
| 部分失败语义 | 有成功项返回 200 + 明细；**全部失败返回 422** |
| 前端 | 列表多选 → 批量改状态/负责人/删除，失败时展示首条失败原因 |

### 2.8 数据导出

| 能力 | 实现 |
| --- | --- |
| 导出资源 | 需求、工作项、测试用例、成员、项目、活动日志 |
| 参数一致 | 复用列表接口的筛选参数，**导出口径与页面所见一致** |
| 编码 | `text/csv; charset=UTF-8` + **UTF-8 BOM**（Excel 直接打开不乱码） |
| 表头 | 取自校验规则表，保证与接口字段一一对应 |
| 成员效能报表 | 独立聚合视图 `/api/export/metrics/members` |

### 2.9 用户与组织管理

新增成员（可指定初始密码）、编辑资料、改角色、**启用/停用**、**重置密码**、删除；账号格式与唯一性校验；最后一名管理员保护；密码永不回显。

### 2.10 各业务模块补全

| 模块 | 本轮补齐 |
| --- | --- |
| 项目 | 工作项**详情抽屉**（描述/状态流转/关联/评论）、**迭代 CRUD + 复制**、批量操作、导出、看板拖拽约束 |
| 产品 | **真实 RTM**（替换假矩阵）、需求追溯抽屉、批量删除、导出 |
| 测试 | 计划**用例增删**、导出用例 |
| 知识 | 页面**删除**、**新建子页面**、空间删除、父子约束提示 |
| 协作 | 评论删除（作者/管理员） |
| 效能 | 导出改走后端接口，口径统一 |
| 后台 | 成员 CRUD、**权限矩阵由服务端下发**、导出成员 |
| 全局 | 搜索类型过滤 + 条数上限、导航权限过滤、按钮权限显隐 |

## 三、可维护性改进

| 项 | 说明 |
| --- | --- |
| `SchemaMigrator` | 基于 `information_schema` 的**幂等结构迁移**，解决 MySQL 不支持 `ADD COLUMN IF NOT EXISTS` 的问题；自动补 `plm_user.enabled`、清理已合并的历史表 |
| 统一启动顺序 | `@Order(0)` 迁移 → `@Order(1)` 种子数据，避免首次启动顺序不确定 |
| 权限单一来源 | 角色权限只定义在 `PermissionService`，接口下发 + 拦截校验共用同一份数据 |
| 校验单一来源 | 字段规则只在 `Schemas.java` 定义，校验、筛选白名单、导出表头三处共用 |

## 五、图表体系升级（ECharts）与详情视图

### 5.1 从手写 SVG 迁移到 ECharts

原先的图表是手写 SVG（柱状 / 折线 / 环形 / 进度环），虽然可用但能力有限：无 tooltip、无交互、无下钻、坐标轴需手工计算。

现已**全量迁移到 ECharts 6**，统一收敛在三个文件：

| 文件 | 职责 |
| --- | --- |
| `utils/chartOptions.js` | 调色板、字体、tooltip、坐标轴、7 种图表的 option 构造器 |
| `components/EChart.js` | 通用容器：实例生命周期（init / setOption / resize / dispose）+ 点击事件 |
| `components/charts.js` | 业务图表组件（BarChart / LineChart / Donut / Gauge / RadarChart / ScatterChart） |

**双模式适配**：`echarts` 通过 importmap 指向 `vendor/echarts.js`（浏览器原生 ESM），在 Vite 下由 `node_modules` 解析，两套模式共用同一份源码。

**统一视觉**：所有图表共享薄荷绿调色板、玻璃质感 tooltip（`backdrop-filter`）、虚线网格、圆角柱体与渐变面积。

## 六、工作项子项（父子结构）

### 6.1 补齐前的缺口

原先工作项只有 `子任务` 这个**类型标签**，**没有任何父子结构**：

- 没有 `parentId` 字段，无法表达"这条属于哪条"
- 界面上的"子任务"只是一个普通工作项，无法汇总、无法折叠
- 项目进度把父项与子任务一起计入分母，存在重复计算

### 6.2 数据模型

`plm_work_item` 新增 `parent_id`（可空）+ 索引 `idx_work_item_parent`。
老库由 `SchemaMigrator` 幂等补列与补索引，无需手工改表。

### 6.3 业务规则

| 规则 | 说明 |
| --- | --- |
| 层级上限 | **最多两层** —— 「子任务」不能再挂子项 |
| 同项目约束 | 子项必须与父项属于同一项目 |
| 禁止自引用 | 父项不能是自身 |
| 环路防护 | 沿父链向上检测，防止循环引用 |
| 类型归一化 | **有父项 ⇔ 类型为「子任务」**，后端自动保持一致，杜绝"无父项的子任务"这类矛盾数据 |
| 父项关闭门禁 | 父项仍有未完成子项时，流转到「已完成」返回 **422** |
| 删除约束 | 父项仍有子项时删除返回 **409**（提示先删或移出子项） |
| 统计口径 | 项目进度与故事点**只统计顶层工作项**；子任务完成不改变项目进度 |

### 6.4 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/work-items/tree?projectId=` | 项目工作项树：顶层 + 子项 + 每项的子项汇总 + 统计 |
| `GET` | `/api/work-items/{id}/children` | 子项列表 + 汇总（总数/已完成/进度/点数/allDone） |
| `GET` | `/api/work-items/{id}/tree` | 自身 + 子项 + 父项 + 兄弟项 |
| `GET` | `/api/work-items/{id}/subtask-summary` | 仅子项汇总 |

### 6.6 顺带修复的历史缺陷

排查子任务"移出"功能时发现两个**通用**问题（影响所有可空引用字段，如"取消迭代归属"）：

| 缺陷 | 根因 | 修复 |
| --- | --- | --- |
| 可空字段无法被清空，`{"parentId": null}` 返回 400「没有需要更新的字段」 | `Validator` 在 PATCH 时对空值一律 `continue`，字段根本没进更新集合 | 区分"未传"与"显式传空"：显式传空的可空字段进入更新集合；必填字段显式传空则报校验错误 |
| 即使通过校验，数据库里也没被置 NULL | `updateById` 默认 `NOT_NULL` 字段策略会跳过 null 字段 | 记录被显式清空的字段，额外用 `UpdateWrapper.set(col, null)` 单独置空 |
